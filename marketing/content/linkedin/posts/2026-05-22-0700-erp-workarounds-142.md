Troubleshooting a Yardi CAM calculation by starting with the tenant is backwards.

The correct starting point is the recovery pool. the layer where errors affect every tenant simultaneously.

Yardi processes CAM calculations through five configuration layers in sequence: recovery pool, charge code, lease setup, billing setup, and manual overrides. A correct output at each layer depends on the layer above being correct. Fixing Layer 3 when the error is in Layer 1 does not help.

Layer 1 errors (recovery pool) are the highest-impact: wrong GL accounts in the pool, variable expenses classified as fixed, gross-up threshold set to 90% when leases specify 95%, occupancy type set to Physical instead of Economic. Every tenant in the pool is affected.

Layer 2 errors (charge code) break the link between the billing and the pool calculation. If the recovery code field is blank, the charge code cannot pull pool data. The tenant is billed from a static amount instead of the calculated recovery.

Layer 3 errors (lease setup) affect individual tenants: denominator not updated after expansion, wrong denominator type, tenant square footage not updated after remeasurement.

Layer 4 (billing setup) affects invoice frequency and estimate method but not the underlying calculation.

Layer 5 (manual overrides) tenant-specific exceptions. override everything above them. An override from a prior lease term that was never removed will produce incorrect results even when the pool is correctly configured.

The systematic check: export total expenses from the recovery pool, independently export total operating expenses from the GL, compare. A gap points to unmapped accounts or incorrect exclusions. Fix those before checking any other layer.
