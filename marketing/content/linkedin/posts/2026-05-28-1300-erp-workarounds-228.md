Most Yardi CAM errors aren't calculation errors. They're configuration errors that produce correct-looking wrong numbers.

Yardi calculates accurately. The problem is what it's configured to calculate.

Six configuration points that produce material errors:

GL account mapping: operating expenses that aren't mapped to the recovery pool. Every dollar in an unmapped account disappears from the pool. The calculation balances. The recovery is wrong.

Charge code chain: if a charge code isn't linked through CAM Pool to Billing Code to Lease Charge, the recovery doesn't reach the tenant. No error message. The charge code simply doesn't bill.

Occupancy snapshot: Physical occupancy takes a point-in-time reading, typically the first of the month. Economic occupancy uses the rent roll-weighted average for the period. On a 200,000 SF building with 15% vacancy, Physical and Economic occupancy can diverge by 4-5 percentage points. a $43,200 annual difference on a $600,000 variable expense pool.

Gross-up configuration: if fixed expenses are classified as variable, they get grossed up. Property taxes and insurance premiums don't vary with occupancy. Applying gross-up to them inflates the pool for every tenant, every year.

Cap escalation base: if the base year amount isn't updated at lease renewal, the cap calculated from that base produces the wrong ceiling every year the lease is active.

Pro-rata denominator: if the denominator isn't updated when space is added, removed, or remeasured, every pro-rata calculation for every tenant in that pool is wrong.

None of these produce error messages in Yardi. The system processes them and produces output. The output is wrong.
