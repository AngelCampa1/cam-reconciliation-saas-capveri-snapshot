From Angel Campa, CapVeri founder:

A contrarian position worth defending: the answer to CAM reconciliation problems is not better software in your ERP.

This is a common vendor pitch: your ERP has a CAM module, but it's configured wrong or underutilized. The fix is better training, better templates, or an add-on module that runs validation checks within the system.

The problem with this framing is that it locates the solution in the same system that contains the configuration errors.

The gross-up threshold in Yardi is wrong. The fix is not a Yardi add-on that validates gross-up thresholds, because the validation is running inside the same system with the same configuration. If the threshold is set to 1.02 when it should be 1.0, a validation module built on Yardi's data layer is going to see 1.02 as the correct value, because that's what's in the system.

The only way to catch configuration errors is to run a calculation that doesn't start from the ERP configuration. An independent layer reads the lease terms directly and runs the math from those terms. It then compares its output to the ERP output. Any difference is a finding.

This is not a criticism of Yardi, MRI, or any other ERP. They're general-purpose systems that can be configured to handle a wide range of lease structures. The limitation is inherent to the model: a system can only check its own configuration against itself if it has an independent reference for what "correct" means.

The lease is the independent reference. The ERP doesn't read the lease. It reads its own configuration.

An independent calculation layer that reads the lease is not a replacement for the ERP. It's the check that the ERP can't run on itself.

That's the position CapVeri is built on. Whether you end up using CapVeri or not, the logic applies: the verification step has to be independent to be meaningful.
