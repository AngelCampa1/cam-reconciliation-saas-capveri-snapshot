The most dangerous CAM reconciliation error is not the one that looks obviously wrong. It's the one that goes into the system clean and produces a statement that reconciles.

A cap rate entered as 5 instead of 0.05 does not flag a validation error. The system accepts it. It sets a 500% cap, which is no cap at all. The tenant's statement shows a number. The math checks out. The only problem is the cap is invisible.

The same applies to gross-up applied when the building is already at target occupancy. Factor of 1.03 on a $200,000 pool adds $6,000 in charges that shouldn't exist. No alert. No exception report. Statement looks complete.

These aren't calculation errors. They're input errors that produce calculation outputs. The calculation was right. The inputs were wrong.

The practical fix: after generating statements, run a two-step check. First, pull the cap rate from every lease and compare it to what's in the system. Values above 2.0 are almost certainly wrong. Values of exactly 5 or 10 are the textbook mistake. Second, compare actual occupancy to the gross-up threshold. If actual >= target, no gross-up should apply. Any factor above 1.0 in that case is an error.

Thirty minutes. Catches the two errors that produce the most formal tenant disputes.
